# Probes

Load when running the texture-coordinate, pack-source or pack-icon probe - `TexCoordProbeMixin`,
`TexCoordProbeBlendMixin`, `SelectHarnessPacksMixin`, `PackSourceSweep`, `PackIconSweep`. The
pitch-roll probe is the session-refresh checklist's. Indexed from
[`harness/CLAUDE.md`](../../harness/CLAUDE.md).

- Texture-coordinate probe: `./gradlew runRenderReferences -PrefharnessTexCoordProbe=u -PrefharnessOutputDir=<dir>` from `harness/`, its own wrapper (or `=v`), with any mode. `TexCoordProbeMixin` replaces the colour of `core/entity`, the one fragment program every entity pass compiles, with the interpolated texture coordinate's whole `float`, and `TexCoordProbeBlendMixin` draws every pipeline with blending off while the switch is set. What a pixel holds, how to decode it and how to read a texel boundary from it are asset-renderer's [renderer/TexCoordProbe.md](../renderer/TexCoordProbe.md). One boot per axis. **Point the output outside the reference tree**: nothing on the asset side forwards the switch, and a run written into `references/` would replace ground truth with coordinate bits.
- Pack-source probe: `./gradlew renderVanillaPackSources [-PrefharnessPacks=a.zip,b] [-PrefharnessPackDir=<dir>]` from asset-renderer, then `./gradlew packSourceParityVanilla`. The one run that loads resource packs, and it draws nothing: `PackSourceSweep` writes `pack-sources/sources.json` beside the reference tree - for every resource under `atlases/`, `blockstates/`, `equipment/`, `items/`, `models/` and `textures/`, the stack of packs `ResourceManager.listResourceStacks` answers, lowest first, each with the SHA-256 of what it supplies. The packs default to the packs dump's three fixtures under `cache/asset-renderer/packs/`; the client discovers them through `--resourcePackDir` exactly as it would a player's, and `SelectHarnessPacksMixin` selects them on top of `options.txt`'s at boot. **The selection touches the pack repository and never `Options.resourcePacks`**, so the shared run directory keeps no trace of it - a pack persisted there would load into the next vanilla render. `HarnessMode.resolve` refuses packs beside any mode but the two pack modes for the same reason.
- Pack-icon probe: `./gradlew renderVanillaPackIcons [-PrefharnessPacks=a.zip] [-PrefharnessPackDir=<dir>]` from asset-renderer, then `./gradlew packIconParityVanilla`. The ground truth for a block item a pack gives a definition of its own, defaulting to Hypixel+ under `cache/texturepacks/`. The run first writes asset-renderer's roster, `pack-icons/roster.json` beside the reference tree - each such item with no stack, and with every stack `LeafStacks` solves a leaf of the pack's definition to at the slot - then boots `PACK_ICONS` with the roster's packs, and `PackIconSweep` draws every roster stack through `ItemFrameRenderer` into `pack-icons/<key>.png`. **The stack is the client's own reading of the roster**: `TagParser` parses the SNBT, `DataComponentPatch.CODEC` decodes it against the running registries and `applyComponentsAndValidate` applies it, so a stack the client refuses is a failed subject rather than a drawing of something else. A roster solved over other packs than the run selected is refused before anything draws.
