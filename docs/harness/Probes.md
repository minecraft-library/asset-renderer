# Probes

Load when running the texture-coordinate, pack-source or pack-icon probe or the pack-tooltip run -
`TexCoordProbeMixin`, `TexCoordProbeBlendMixin`, `SelectHarnessPacksMixin`, `PackSourceSweep`,
`PackIconSweep`, `TooltipSweep`'s pack configuration. The pitch-roll probe is the session-refresh
checklist's. Indexed from
[`harness/CLAUDE.md`](../../harness/CLAUDE.md).

- Texture-coordinate probe: `./gradlew runRenderReferences -PrefharnessTexCoordProbe=u -PrefharnessOutputDir=<dir>` from `harness/`, its own wrapper (or `=v`), with any mode. `TexCoordProbeMixin` replaces the colour of `core/entity`, the one fragment program every entity pass compiles, with the interpolated texture coordinate's whole `float`, and `TexCoordProbeBlendMixin` draws every pipeline with blending off while the switch is set. What a pixel holds, how to decode it and how to read a texel boundary from it are asset-renderer's [renderer/TexCoordProbe.md](../renderer/TexCoordProbe.md). One boot per axis. **Point the output outside the reference tree**: nothing on the asset side forwards the switch, and a run written into `references/` would replace ground truth with coordinate bits.
- Pack-source probe: `./gradlew renderVanillaPackSources [-PrefharnessPacks=a.zip,b] [-PrefharnessPackDir=<dir>]` from asset-renderer, then `./gradlew packSourceParityVanilla`. It loads resource packs and draws nothing: `PackSourceSweep` writes `pack-sources/sources.json` beside the reference tree - for every resource under `atlases/`, `blockstates/`, `equipment/`, `items/`, `models/` and `textures/`, the stack of packs `ResourceManager.listResourceStacks` answers, lowest first, each with the SHA-256 of what it supplies. The packs default to the packs dump's three fixtures under `cache/asset-renderer/packs/`; the client discovers them through `--resourcePackDir` exactly as it would a player's, and `SelectHarnessPacksMixin` selects them on top of `options.txt`'s at boot. **The selection touches the pack repository and never `Options.resourcePacks`**, so the shared run directory keeps no trace of it - a pack persisted there would load into the next vanilla render. `HarnessMode.resolve` refuses packs beside any mode but a pack mode for the same reason.
- Pack-icon probe: `./gradlew renderVanillaPackIcons [-PrefharnessPacks=a.zip] [-PrefharnessPackDir=<dir>]` from asset-renderer, then `./gradlew packIconParityVanilla`. The ground truth for a block item a pack gives a definition of its own, defaulting to Hypixel+ under `cache/texturepacks/`. The run first writes asset-renderer's roster, `pack-icons/roster.json` beside the reference tree - each such item with no stack, and with every stack `LeafStacks` solves a leaf of the pack's definition to at the slot - then boots `PACK_ICONS` with the roster's packs, and `PackIconSweep` draws every roster stack through `ItemFrameRenderer` into `pack-icons/<key>.png`. **The stack is the client's own reading of the roster**: `TagParser` parses the SNBT, `DataComponentPatch.CODEC` decodes it against the running registries and `applyComponentsAndValidate` applies it, so a stack the client refuses is a failed subject rather than a drawing of something else. A roster solved over other packs than the run selected is refused before anything draws.
- Pack-tooltip run: `./gradlew renderVanillaPackTooltipsHypixelSkyblock [-PrefharnessPackDir=<dir>]` from asset-renderer, then `./gradlew tooltipHypixelSkyblockParityVanilla`. It is no probe: its drawings are the ground truth a stored gate is measured against, so a capture of that gate runs it. The run boots `PACK_TOOLTIPS` with hypixel-skyblock selected over vanilla - its name fixes the pack, so it honours no `-PrefharnessPacks` - **from a copy of the pack, never the fixture itself**. hypixel-skyblock recolours text through `core/text.vsh`, a program no 26.1 pipeline loads: the client's text pipelines name `core/rendertype_text`. So `packTooltipPacks`, which the run depends on, copies the pack from `-PrefharnessPackDir` (default `cache/asset-renderer/packs/`) into `pack-tooltip-packs/` beside the reference tree with that shader also at `core/rendertype_text.vsh`, and the run hands the client that folder: the real client runs the pack's own colour swap, and the fixture stays the pack as published. Only the vertex shader is placed - vanilla's `rendertype_text.fsh` reads exactly what the pack's shader writes, and 26.1 builds its programs in code. `TooltipSweep`, constructed for the run's packs, draws the tooltip roster's `hypixel-skyblock` section, each subject whole and as its box alone, into `pack-tooltips/hypixel-skyblock/` beside the reference tree. A pack subject names an unstyled roster subject by key and draws that subject's lines, so a pack drawing and the vanilla reference of its key carry one text. **Before the first drawing the sweep writes `stack.json` beside them**: the pack selection `PackSourceSweep` records, written through that probe's own selection block, and for every tooltip sprite the section reaches the id the client's tooltip draws - read through `TooltipRenderUtilAccessor` from the client's own style-to-sprite helpers rather than restated - the stack of packs supplying its file, lowest first with each one's SHA-256, and the scaling of the sprite the client stitched. The scaling is the stitched sprite's parse rather than a hash of its sidecar, because the parse is what the client's GUI blit reads, whichever pack's sidecar it paired with the PNG. Then the file the client compiles its GUI text pipeline's vertex shader from - read off the pipeline, never named - with the stack of packs supplying it, and the stack of every shader program and include a selected pack ships. The asset side loads the same packs from the folder the handshake names - the derived copy - and, before it compares a pixel, refuses a configuration whose chrome it resolves from another pack, with other bytes or at another scaling, whose text palette it reads from another text shader than the client runs, or whose shader files it resolves from another pack or with other bytes. **Every line the section reaches is printable ASCII**: the pack's font adds icon glyphs the client would draw and the renderer draws no font from a pack, and `TooltipParitySweepTest` holds the rule over the tracked roster.
